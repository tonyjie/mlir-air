1. SmolVLA 是什么？

SmolVLA 是一个「视觉-语言-动作」模型（Vision-Language-Action, VLA） —— 你可以把它想成 机器人的大脑。它来自 Hugging Face 的 LeRobot 生态。

一句话类比： 你对一个机械臂说「把方块捡起来」，同时给它几个摄像头画面。SmolVLA 读懂 画面 + 这句话 + 机器人当前姿态，然后输出接下来一连串该怎么动（关节角度、夹爪开合）。 它把「看 + 听懂 + 决定怎么动」合成了一个模型。
输入 / 输出（本项目用的 lerobot/smolvla_base 版本，450M 参数）：
  • 输入：3 路相机图像 + 一句自然语言指令 + 机器人状态向量（6 维）
  • 输出：一个「动作块」(action chunk) —— 一次预测未来 50 步动作，每步 6 个数

它用一种叫 flow-matching（流匹配）的方法生成动作：从随机噪声开始，迭代 10 步逐渐「去噪」成一串合理的动作 —— 类似 AI 画图里的扩散过程，只不过这里「画」的是机器人动作。

2. 模型的三个部分

SmolVLA 内部由三块拼成，就像一条流水线：

为什么 backbone 是「语言模型」？

SmolVLA 的第二段其实就是一个精简版的大语言模型（SmolLM2-360M，和 Llama 同类架构）。 区别在于：它不「说话」（不生成文字），而是把图像、文字、状态一次性读进去、理解一遍， 产出一份「理解结果」交给动作专家。因为团队已经在 NPU 上部署过好几个同类语言模型 （Llama、Qwen 系列），这一段是最有把握、最能复用现成积木的部分 —— 所以我们先攻它。

3. 为什么要搬到 NPU？什么是 NPU？

CPU vs NPU 类比： CPU 像一个全能的通才，什么都能算，但一次做的事有限。 NPU（Neural Processing Unit，神经网络处理器）像一个专门算矩阵乘法的车间 —— AI 模型的绝大部分计算就是矩阵乘法，NPU 为此专门设计，又快又省电。机器人要实时反应， 把模型放到 NPU 上是关键一步。

我们用的芯片是 AMD NPU2（代号 Strix，架构 AIE2P），编译工具链是 mlir-air —— 它负责把「模型里的一个算子」翻译成「NPU 上一段能跑的机器码」。

4. 我们的方案：CPU / NPU 混合

我们没有把整个模型都搬上 NPU，而是做了一个混合流水线： NPU 跑最核心、最值得的语言 backbone； CPU 跑其余部分。这是刻意的工程取舍，不是没做完。

哪些在 NPU，哪些在 CPU？

5. 怎么把 backbone 映射到 NPU（分阶段）

我们没有一步到位，而是像搭积木一样、每一步都先验证正确再往上加。整个过程分 4 个阶段：

0建 CPU 参考（「标准答案」）

先在纯 CPU 上跑真实的 SmolVLA，把每一层的输出录下来当「标准答案」(oracle)。 后面 NPU 每算一步，都要和这个标准答案对照。✅ 完成

💡 这一步就抓出一个关键坑：模型配置文件写着 RoPE 参数是 100000，但代码运行时其实用的是 10000 —— 靠对照标准答案的相似度才发现。用错会让整个 backbone 悄悄算歪。

1验证每个「积木」kernel

backbone 需要 8 类基础运算（矩阵乘法、归一化、RoPE、激活……）。其中 7 类是现成的、 在 NPU 上验证过的积木，只需按 SmolVLA 的新尺寸重测一遍。唯一全新的是「非因果注意力」 —— 我们没有硬改复杂的现成注意力，而是用「矩阵乘法 + 带掩码的 softmax」组合出来，更稳。 ✅ 完成

2拼出「一层」，对照标准答案

把积木拼成 backbone 的第 1 层，在 NPU 上跑，和标准答案的第 1 层比。 相似度 0.99998（1.0 是完全一致）—— 说明拼装正确。✅ 完成

3扩到 16 层，端到端跑通

把一层复制成完整 16 层，NPU 算出的每层 K/V「记忆」注入回 CPU 的动作专家， 产出最终动作块，和纯 CPU 的动作块对照。✅ 完成

💡 我们还做了个「扰动测试」：故意把 NPU 算的 K/V 换成乱数，动作块立刻大变 —— 这证明动作确实由 NPU 的计算驱动，不是 CPU 偷偷在算。

6. 正确性：怎么保证没算错

NPU 用 bf16（16 位）计算，比 CPU 的 32 位精度低，所以我们要证明「误差在可接受范围内」。 用两条独立的标尺：

结论：正确性有保证。 相似度 0.9971（越接近 1 越好，门槛设 0.99）， 误差全部来自 bf16 精度、在预期内。而且这些数字是在真实 NPU 硬件上测的，不是模拟。

7. 性能：优化前后

这个项目先保证正确，再优化速度。第一次测速时，NPU 反而比 CPU 慢一点 —— 因为注意力部分把 15 个「注意力头」拆成很多次小任务发给 NPU，「发任务」的开销累积起来很大 （每层要发 31 次，16 层约 500 次）。

类比： 就像你有 15 份小文件要打印，每份都单独走一趟打印机 —— 走路的时间比打印还久。 优化就是把能合并的合并成一叠一次打印。

优化（路线 1）： 这 15 个注意力头里，每 3 个共享同一份数据，可以堆叠成一次大矩阵乘法。 于是每层的「发任务」次数从 31 降到 11，总共从约 528 降到约 208 次。

指标优化前优化后
NPU backbone 延迟（16 层）~400 ms~226 ms
CPU backbone 延迟（同样计算）~344 ms~340 ms
NPU / CPU 比值1.16×（NPU 慢）0.71×（NPU 更快）
注意力「发任务」次数 / 层3111
正确性（make verify）PASSPASS（逐位一致）
优化结果：NPU backbone 从 400ms 降到 226ms（约 1.8× 加速），现在比 CPU 更快。 而且优化后正确性数字逐位不变 —— 因为「合并发任务」只是换了个发法，算的还是同一道题。
还有空间（未做）： 目前还剩约 208 次「发任务」。下一步（路线 3）可以把整层的注意力也 融进一个更大的 NPU 程序块里，进一步减少开销。这是后续优化方向。
