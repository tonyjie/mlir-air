SmolVLA — 模型架构说明

A model-first walkthrough of HuggingFace LeRobot's SmolVLA (~450M Vision-Language-Action model). 本文档只讲模型本身：它由什么组成、每个子模块的算子 / shape / dtype / 参数量。不涉及 NPU 实现（本 repo 暂未部署 SmolVLA）。

⚠️ 关于准确性 / On accuracy. 所有数值均来自官方源（arXiv 2506.01844、HuggingFace blog、lerobot/smolvla_base/config.json、SmolVLM2-500M-Video-Instruct/config.json、lerobot 源码）。少数无法从 config 直接读出的值（如 SigLIP 内部层数）已在 D2 明确标为「推断」。常见误传修正：action expert 宽度是 720（= 0.75 × 960），不是某些三方文章写的 576——因为 backbone 文本维度是 960 而非 768。

Part A — 模型总览 (Model Overview)

A1. SmolVLA 是什么

SmolVLA 是一个 Vision-Language-Action (VLA) 机器人策略模型：输入是多路相机图像 + 一句自然语言指令 + 机器人本体状态 (proprioceptive state)，输出是一段连续动作序列 (action chunk)。它把一个预训练 VLM 当作「感知 + 语言理解」的大脑，再接一个轻量 action expert 把多模态特征翻译成电机指令。

它由两大组件构成：

  • VLM backbone SmolVLM2-500M-Video-Instruct — 由 SigLIP vision encoder + SmolLM2 语言 decoder 组成。SmolVLA 只用其语言 decoder 的前 16 层（共 32 层）。
  • Action expert ~100M 的小 transformer，用 flow-matching 目标训练，输出动作。它在部分层复用 VLM 的 KV 来读取多模态上下文。

与纯 LLM（如 Llama-3.2-1B）相比，关键区别：

  • 多模态输入：不是 token 序列，而是 图像 patch + 文本 token + state token 拼成的前缀 (prefix)。
  • 输出是连续动作：不是 vocab 上的 logits + 采样，而是 flow-matching 用 Euler 积分 10 步生成的实数向量序列。
  • 双塔交错：VLM 和 action expert 是两个不同宽度的 transformer，通过 cross-attention 在每隔一层耦合。

B1. Vision encoder — SigLIP

每路相机图像（resize + pad 到 512×512）送进 SigLIP-base-patch16-512：

属性值说明
模型google/siglip-base-patch16-512SmolVLM2-500M 的视觉塔
hidden_size768vision embedding 宽度
image_size / patch_size512 / 16→ (512/16)² = 1024 patch/帧
num_heads12vision attention heads
num_layers / intermediate12 / 3072推断 来自 SigLIP-base 规格，非 checkpoint 直读
connectorPixelShuffle ×4scale_factor=4，1024 patch → 64 token/帧

PixelShuffle 的作用：把 1024 个 patch token 在空间上 4×4 合并降采样到 64 个，大幅减少喂给语言塔的视觉 token 数（3 路相机 = 192 个视觉 token）。SmolVLA 运行时只用全局图像，不做 tiling。

B2. Language decoder — SmolLM2

视觉 token + 文本 token + state token 拼成 prefix，过 SmolLM2 风格的 decoder。它是标准 Llama 家族 block：RMSNorm + GQA 注意力(RoPE) + SwiGLU FFN。SmolVLA 只跑前 16 层（backbone 实际有 32 层），attention 在这 16 层填好 prefix 的 KV cache 供 action expert 读取。

层裁剪 (layer truncation). 只用前 16/32 层 是 SmolVLA 省算力的关键设计之一——多模态感知不需要语言塔的全部深度。这与 Llama 部署「用满所有层」不同。

B3. 一个 LM block 的算子与 shape

下图是 VLM backbone 中一个 decoder 层（×16）。符号见 A2：D=960, H=15, H_kv=5, d_h=64, F=2560。P = prefix 长度（≈ 192 视觉 + 文本 + 1 state）。

逐算子说明 (per-kernel)

RMSNorm
  • Shape: [B,P,D]→[B,P,D], γ:[D]
  • Op: y = x·rsqrt(mean(x²)+ε)·γ，沿 D=960 逐行；无均值减、无 bias
Q / K / V projection (GEMM)
  • Shape: Q [D,960]，K/V [D,320]（GQA：KV 比 Q 窄，5×64=320）
  • Op: Y = X @ W，无 bias；prefill 是 M=P 的 GEMM
RoPE
  • 作用于 Q、K 的每个 head（d_h=64），θ=100000；V 不旋转
GQA scaled-dot-product attention
  • causal mask；每 3 个 Q head 共享 1 个 KV head；无权重
  • 关键：这 16 层产出的 prefix K/V 是 action expert cross-attn 的输入
SwiGLU FFN
  • gate/up [D,2560]，SiLU(gate)·up，down [2560,D]

Part C — Action Expert

C1. Action expert 总体

Action expert 是一个 16 层、宽度 720 的 transformer，结构镜像 SmolLM2 block（RMSNorm + RoPE + SwiGLU），但更窄（0.75×960）。它不处理图像/文本——那是 VLM 的活——它处理的是 flow-matching 的含噪动作 (noisy action)，并通过 cross-attention 去「看」VLM 已经算好的多模态特征。

属性值
层数16（= num_vlm_layers）
hidden dim D_x720
head 几何沿用 VLM：15 Q / 5 KV / d_h 64
训练目标conditional flow matching（非 DDPM 扩散）
训练策略train_expert_only=true，freeze_vision_encoder=true（base ckpt）

C2. Self-attn / Cross-attn 交替

由 self_attn_every_n_layers=2 + attention_mode="cross_attn" 控制：

  • 偶数层 (idx % 2 == 0) → self-attention：动作 token 之间互相注意。
  • 奇数层 → cross-attention：Query 来自 expert 自己的动作 token，Key/Value 来自冻结的 VLM prefix KV（图像+文本+state 的上下文）。

这就是 SmolVLA「复用 VLM KV」的含义——cross-attn 层不重新编码图像/文本，直接读 VLM backbone 算好的 K/V，省掉重复计算。

C3. Flow-matching 动作头

SmolVLA 不在 vocab 上采 token，而是用 conditional flow matching 生成连续动作。推理时从纯噪声 t=1 沿学到的速度场 v_t Euler 积分到 t=0，共 num_steps=10 步。

路径上的投影（flow 头，在 transformer block 之外）

模块Shape说明
action_in_proj[32, 720]noisy action（pad 到 32）→ expert 宽度
timestep embedsinusoid → [720]min_period=4e-3, max_period=4.0
action_time_mlp_in[1440, 720]concat(action, time)=1440 → 720
action_time_mlp_out[720, 720]SiLU 后再投影
action_out_proj[720, 32]expert 输出 → 速度场 v_t（动作维度）
state_proj[32, 960]state（pad 到 32）→ VLM 宽度，作 1 个 prefix token

最终动作 chunk 形状 [B, 50, ≤32]，切到真实动作维度（base 模型 SO-100 为 6）。

C4. 一个 expert block 的算子与 shape

每层结构（D_x=720，head 几何沿用 VLM 的 15/5/64）：

input RMSNorm — γ:[720]
注意力（偶=self / 奇=cross）
  • self (偶层): Q/K/V/O 在 720 宽度上投影，按 VLM head 几何切头，RoPE(θ=10000)
  • cross (奇层): Q 来自 expert 动作 token [720→H·d_h]；K/V 由 VLM KV（宽 320）重投影进注意力空间；O 投回 720
post-attn RMSNorm — γ:[720]
SwiGLU FFN — gate/up [720, F_x]，down [F_x, 720]，SiLU

不确定 F_x 与 expert 自注意力在 720 宽度下投影的精确 in/out 维度由 build 时的 Llama-SwiGLU 取整规则算出，非 config 静态数。需精确整数时请实例化 SmolVLAPolicy 后打印模块确认。

Part D — 参考 (Reference)

D1. 算子清单汇总

把 SmolVLA 用到的 leaf 算子按类型汇总（与纯 LLM 高度重合，这也是它适合复用 LLM kernel 的原因）：

算子出现位置典型 shape（per token / per 层）类比 LLM kernel
RMSNormVLM 层 ×2，expert 层 ×2，finalγ:[960] 或 [720]RMSNorm
GEMM (Q/K/V/O)VLM + expert 注意力[960,960]/[960,320]；expert 720 宽GEMM / GEMV
RoPEVLM + expert self-attnd_h=64，θ=100000 / 10000RoPE
GQA attentionVLM self；expert self/cross15 Q / 5 KV / 64FlashAttention (GQA)
SwiGLU FFNVLM + expertgate/up [960,2560]；expert [720,F_x]SiLU + Mul + GEMM
Linear proj（flow 头）action_in/out, time MLP, state_proj见 C3 表GEMM / GEMV
SigLIP vision图像编码768d / patch16 / 12 层(ViT：GEMM+LayerNorm+GELU+attn)
PixelShufflevision connector×4 空间合并(reshape/重排，非 matmul)
观察. 除 SigLIP vision 塔（ViT 风格，用 LayerNorm + GELU）和 PixelShuffle 外，SmolVLA 的语言塔和 action expert 都是 Llama 家族算子（RMSNorm / RoPE / GQA / SwiGLU），与本 repo kernel_registry 已有的 leaf kernel 同族。差异点在于：① cross-attention 复用外部 KV；② flow-matching 的若干小 Linear + 时间嵌入；③ vision 塔是独立子系统。
