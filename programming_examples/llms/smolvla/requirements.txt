# Additional Python packages for the SmolVLA example.
#
#     pip install -r requirements.txt
#
# WHERE to install it: a SEPARATE virtualenv, not the mlir-air environment.
# ------------------------------------------------------------------------
# This example runs the NPU vision stage in-process inside the lerobot model,
# so ONE interpreter needs both sides -- torch + lerobot, and air + pyxrt. The
# way to get that is NOT to add lerobot to the mlir-air environment; it is to
# create a venv for lerobot and source the mlir-air environment before using
# it, which puts air and pyxrt on PYTHONPATH / LD_LIBRARY_PATH so they import
# from that venv:
#
#     python3 -m venv ~/smolvla-venv
#     ~/smolvla-venv/bin/pip install -r requirements.txt
#     source utils/env_setup.sh ...          # makes air + pyxrt importable
#     make verify LEROBOT_PYTHON=~/smolvla-venv/bin/python
#
# Why not just install into the mlir-air environment: lerobot's dependency
# resolution pulls numpy 2.x. A checkout whose mlir-air environment is on
# numpy 1.x (measured: 1.26.4, from an unpinned `numpy` in utils/requirements
# .txt) would have it silently upgraded across a major version, in the
# interpreter every other example and the air/pyxrt C extensions share. If
# your mlir-air environment is already on numpy 2.x, installing in place is
# fine and `make verify` then works with the default LEROBOT_PYTHON=python3.
#
# After this, you still need a one-time HuggingFace setup:
#   1. Create a read token at https://huggingface.co/settings/tokens
#   2. `huggingface-cli login`  (or export HF_TOKEN=<token>)
# The example downloads lerobot/smolvla_base (450M params) on first use.
# See README.md / docs/usage.md for details.
